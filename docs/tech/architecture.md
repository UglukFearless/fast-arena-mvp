# Архитектура

## Компоненты

Во время работы система состоит из трёх компонентов: backend (`FastArena.WebHost`, ASP.NET Core), frontend (собранное Vue-приложение, раздаваемое статическим HTTP-сервером) и PostgreSQL. Браузер обращается только к backend.

## Маршрутизация запросов

OpenAPI-документ со Swagger UI и статические файлы из `wwwroot` — изображения портретов, существ и предметов по путям `/assets/...` — backend отдаёт до маршрутизации. Пути `/api/*` обрабатывают контроллеры. Все остальные пути перехватывает маршрут YARP `{**catch-all}` и проксирует на сервер frontend, который отдаёт SPA. Catch-all перехватывает и `/api/*`, не совпавший ни с одним контроллером, поэтому несуществующий эндпоинт API отвечает страницей SPA с кодом 200.

Приложение и API живут на одном origin.

## Контракт API

Backend публикует OpenAPI-документ, сформированный NSwag по контроллерам и DTO. По нему `FastArena.ApiClientGenerator` генерирует TypeScript-клиент — классы клиентов по контроллерам и типы DTO, — который frontend использует как `src/api/clients.ts`. Поэтому изменение контроллера или DTO доходит до frontend после перегенерации клиента. Запуск генерации описан в [infrastructure.md](infrastructure.md).

## Аутентификация

При входе или регистрации backend выдаёт JWT. Frontend передаёт его в заголовке `Authorization: Bearer` с каждым запросом и проверяет его действительность запросом `GET /api/health/secret-ping`.

## Состояние

Постоянные данные — пользователи, герои, их предметы и экипировка, каталог предметов и монстров, портреты, результаты боёв — хранятся в PostgreSQL.

Сессия активности, включая состояние текущего боя по раундам и активные эффекты, хранится в памяти процесса backend. Перезапуск backend теряет все незавершённые сессии; несколько экземпляров backend не видят сессий друг друга. В базу данных бой попадает при финализации: результат боя, награда и изменения героя. Исключение — расход предмета из кармана: он записывается в базу в раунде использования, поэтому после перезапуска backend сессия теряется, а предмет остаётся израсходованным.

Хранилища Pinia на frontend держат копии полученных с backend данных. Навигацию frontend строит по текущей сессии активности, полученной с backend.
