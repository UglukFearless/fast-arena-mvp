# Рабочий цикл

Задача — единица работы с одним согласованным результатом. Оператор — разработчик, ведущий чат.

## Масштаб задачи

Планирование фичи — отдельная задача; её результат — документ изменения. Исполнение одного пункта плана — тоже отдельная задача; её результат — изменения в коде и документации.

Крупная фича не выполняется одной задачей. Сначала выполняется задача планирования, затем по задаче на каждый пункт плана. Разбиение существует затем, чтобы каждая часть прошла собственный сбор контекста и планирование, поэтому цикл проходится целиком для каждой задачи.

## Шаги

1. **Контекст и план.** Сбор контекста, выработка плана. Результат шага — план, изложенный в чате. Шаг выполняется в каждой задаче без исключений, в том числе когда задача исполняет пункт готового плана.
2. **Фиксация.** План и сведения, полученные на шаге 1, записываются в документ изменения; если подходящего документа нет — оператору предлагается его завести. Для пункта готового плана в документ добавляются решения, принятые при планировании этого пункта, — план целиком не переписывается.
3. **Исполнение.** Пункты плана выполняются по одному.
4. **Документация.** Принятые по ходу решения переносятся в документацию разделов.
5. **Ревью кода.** Если менялся код — предложить оператору запустить skill `code-review`.
6. **Ревью документации.** Если менялась документация — предложить оператору запустить агента ревью документации на соответствие [правилам ведения документации](../documentation-rules.md).
7. **Итоги ревью.** Правки по итогам шагов 5–6 согласуются с оператором и вносятся. Внесение правок не запускает новый круг ревью.

Шаг, которому в конкретной задаче нет содержания, пропускается. Пропуск подтверждается оператором наравне с выполнением.

## Чтение по ходу задачи

- Планируется или выполняется изменение кода — читается [code-style.md](../code-style.md).
- Планируется или выполняется изменение документации — читается [documentation-rules.md](../documentation-rules.md).
- Ведётся документ изменения — читается [индекс work-tracking](../work-tracking/index.md).
- Нужны сведения о проекте — открывается [оглавление документации](../index.md).

## Подтверждение

Ни один шаг не считается завершённым без подтверждения оператора. Переход к следующему шагу без подтверждения запрещён — в том числе переход от документации к коду и от одной партии изменений к следующей.

## Объём изменений

Изменения ограничены задачей: файлы вне её объёма не правятся, попутные улучшения не вносятся. Из решений, удовлетворяющих задаче, выбирается дающее наименьший diff.

## Отклонение от плана

Если при исполнении выясняется, что пункт плана неверен или неполон, исполнение останавливается. Расхождение выносится оператору, принятое решение записывается в документ изменения. Молчаливое отклонение от плана запрещено.

## Недостаток сведений о предметной области

Если задача или документация не объясняют бизнес-смысл сущности, правила или поведения:

1. Задать уточняющий вопрос до реализации. Правила не додумываются.
2. Спросить про конкретный неясный аспект — правило, связь сущностей, граничный случай.
3. После ответа предложить обновление конкретной подстраницы раздела предметной области.
